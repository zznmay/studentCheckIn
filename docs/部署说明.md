## 二、安全提醒（重要）

系统已经暴露在公网，**默认密码 admin/admin123 任何人都能登录**。如果只是临时演示，用完请执行 `停止服务`；如果要长期使用，请务必：

1. 登录后立刻在「账号管理」中修改 admin 密码
2. 修改后重新生成 `data/secret.key`（删除该文件后重启会自动生成，但会使所有已登录用户掉线）

公网地址是 Cloudflare 免费隧道，**重启后会变化**，届时重新运行 `start.sh` 获取新地址即可。

## 三、架构与运行方式

```
浏览器 → Cloudflare 隧道(HTTPS) → 本机 3000 端口 → Node.js 原生 HTTP 服务
                                                    └→ data/*.json 文件持久化
```

- 零第三方依赖，不需要 `npm install`
- 数据存在 `学生考勤平台4.0/data/*.json`，直接备份该目录即可迁移
- 删除 `data/` 后重启，会重新写入演示数据

## 五、为什么没用 Vercel / 静态托管

这个项目是**有状态的 Node.js 全栈应用**：

- 需要写入 `data/*.json`（点名记录、假单、账号）
- 需要服务端签发 token、做权限校验

Vercel 这类 Serverless 平台的文件系统是只读且无状态的，数据会丢。所以采用了「本地常驻进程 + 内网穿透」的方案。

如果后续要正式上生产，建议：

| 场景 | 建议方案 |
|---|---|
| 单校 / 单学院自建 | 一台云服务器（2 核 2G 足够）+ nginx 反代 + systemd 托管 |
| 数据量大 / 并发高 | 把 JSON 存储迁移到 SQLite 或 MySQL（报告里已标注这是当前架构的边界） |
| 无运维资源 | Railway / Render 一类支持持久磁盘的 PaaS |
