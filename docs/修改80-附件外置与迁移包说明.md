# 修改80 说明：附件外置 + 迁移包 zip 化

生效版本：修改80a/80b/80c（2026-10-10）
影响面：数据存储结构、数据备份/迁移包格式

---

## 一、为什么要改

点名确认签名（`attendance.signature`）与考勤异议佐证材料（`appeals[].attachments`）此前以
base64 内嵌在集合 JSON 中，导致：

- 备份包体积随点名次数**线性膨胀**（实测每次点名约 59KB）；
- base64 几乎不可压缩（2.6MB 的包 gzip 后仍2.09MB），迁移必须整包传输；
- 30 份滚动备份每份都拖着全部图片，磁盘占用成倍放大。

---

## 二、存储变化

| 项目 | 改造前 | 改造后 |
|---|---|---|
| 签名 | `attendance.signature` = base64 字符串（约 59KB/条） | `attendance.signatureRef` = `{sha256, mime, size}` |
| 异议附件 | `appeals[].attachments[]` 含 `dataUrl` | `{name, sha256, mime, size}` |
| 图片文件 | 藏在 JSON 里 | `data/attachments/<sha256>`（内容寻址，文件名即 sha256） |

- 同��张图只存一份（sha256 相同即同一文件），写入用「临时文件 + rename」原子落盘。
- `data/attachments/` 属于 `data/` 卷的一部分，**发布时随 data/ 一起移出移回**，发布流程不变。
- 服务启动时自动把存量内嵌数据外置（幂等）；迁移前会自动打一份完整快照，可整体回滚。
- 对外接口响应**完全不变**（读取时回填为 data URI），前端无需改动、显示效果一致。

---

## 三、备份 / 迁移包格式（schemaVersion 2）

数据包不再是一个大 JSON，而是 **zip 容器**：

```
<id>.zip
├── bundle.json# 集合数据（含引用）+ 逐集合 sha256 清单 + 附件清单
└── attachments/
    └── <sha256>            # 图片原始二进制（仅打包被引用的）
```

- **自包含**：迁移到新服务器时附件随包落盘，无需另行拷贝图片。
- **可校验**：预检会逐个核对附件 sha256 与字节数（zip 本身不带 CRC 校验，由本系统补强），
  缺一个附件即拒绝恢复。
- 上传通道支持大文件：192KB 二进制切片（base64 后 256KB）逐片上传 + 整包 sha256 对账，
  网关中断自动重试（连接被掐断后重试即换新连接）。
- 自动备份、灰测归档、迁移包、历史备份列表里的所有包都是 zip 格式。

## 四、迁移操作要点（重要）

| 方式 | 附件是否随迁 | 说明 |
|---|---|---|
| 数据管理页「生成迁移包 → 上传 → 预检 → 恢复」 | ✅ 会 | **推荐**：zip 自包含 |
| 整卷拷贝 `data/` 目录 | ✅ 会 | 含 `attachments/` 子目录 |
| 手工只拷贝 `data/*.json` | ❌ 不会 | 记录引用会指向不存在的文件，图片显示为空 |

> 外置后「只搬 JSON」不再等于「搬全部数据」。请统一走官方恢复通道或整卷拷贝。

迁移后核对方式：

1. 「数据管理 → 数据总览」新增 **附件文件** 一行，显示当前图片数量与体积；
2. 恢复预检界面也会显示「附件文件：当前 N → 恢复后 M」，以及逐个附件的校验结果。

## 五、兼容与回滚

| 场景 | 行为 |
|---|---|
| 导入 v1 旧包（内嵌base64 的纯 JSON） | ✅ 仍可导入，导入时自动转换为引用并落盘 |
| v2 zip 包被旧版本代码导入 | ❌ 不支持（旧代码无法解析 zip），需升级到修改80+ |
| 个别附件文件丢失 | 读取降级为空串并显示占位，系统不崩；该图可从任一含该附件的备份恢复 |
| 需要回滚到旧版本代码 | 先用「附件外置迁移前自动快照」恢复数据（旧代码读不到引用字段），再回滚代码 |
| 附件大面积丢失 | 用含附件的 zip 备份包在新环境恢复（zip 自包含，图片随包回来） |

## 六、验证脚本

```bash
# 起服务（项目副本或本机 3100 端口）后执行
env -u http_proxy -u https_proxy python3 scripts/verify_attachments_zip.py
```

覆盖：存量迁移 → 写入落引用 → 读取回填 → 备份 zip 结构与附件对账 → 分片上传/预检/恢复
→ v1 旧包兼容 → 附件缺失降级 → 异常分支拒绝。

（`scripts/verify_attendance_logs.py` 已适配 zip 下载，按魔数自动分流。）
