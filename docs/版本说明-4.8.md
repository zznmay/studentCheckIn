# 学生考勤工作台 4.8 版本说明

发布日期：2026-10-05
版本定位：**班级管理模块正式版**（代号：修改72）

---

## 一、本版本核心更新

### 1. 新增「班级管理」模块

- **入口位置**：左侧导航「管理」分组，位于「班级名单」之后
- **可见角色**：admin（管理员）、collegeOfficer（学院管理员）
- **列表字段**（7 列）：勾选 / 班级（年级·专业副标题）/ 人数 / 班级岗位 / 状态 / 账号联动 / 操作
- **支持操作**：下载模板、批量导入、新增班级、编辑班级、删除班级、存量迁移、批量同步账号

### 2. 三岗位维护方式变更（重要）

原方式：班主任 / 辅导员 / 纪律委员在「班级名单」中**逐个学生**录入。
新方式：统一在「班级管理」中**按班级维度批量维护**，「班级名单」的三个字段改为**只读展示**。

这项改动的收益：
- 一个班的班主任改了，只需在班级管理改一处，全班学生自动同步
- 避免逐条录入时出现同一班级填写不一致的情况
- 学生表的岗位字段降为「只读镜像」，不再作为权威源

### 3. 权威源与镜像机制

| 层级 | 说明 |
|---|---|
| 权威源 | `classes` 集合（班级管理维护） |
| 只读镜像 | `students` 表（页面展示时由后端按班级覆盖返回，**不落盘**） |
| 写入时机 | 学生新增/修改、Excel 导入、班级管理导入、存量迁移 |

**兼容策略**：`classes` 优先 + `students` 兜底，取并集，**不做硬切换**。
因此历史数据即使未完成迁移，也不会出现字段丢失。

### 4. 账号联动三态

班级管理列表会显示每个岗位与「账号管理」的关联状态：

| 状态 | 含义 | 处理建议 |
|---|---|---|
| `linked` | 岗位人员已建账号，且班级归属一致 | 正常 |
| `no-account` | 岗位人员尚未建账号 | 如需账号，在教职工名单建档后生成 |
| `mismatch` | 有账号但班级归属不一致 | 点「同步账号」修正 |
| `empty` | 该岗位未填写 | 到班级管理补全 |

> **常见情况**：纪律委员通常由学生担任，本就没有教职工账号，
> 因此显示「未建账号」属**正常现象**，不是异常。

### 5. 班级名单导入模板精简

**7 列 → 4 列**：`年级 | 班级 | 姓名 | 学号`

移除的列：纪律委员、辅导员、班主任（三列）

后端仍保留对这三列的读取兜底，因此**旧版模板仍可正常导入**，
导入后三岗位以「班级管理」的权威数据为准。

### 6. 班级状态三态

| 状态 | 含义 |
|---|---|
| `active` | 三岗位齐全，信息完整 |
| `incomplete` | 缺岗位，待补信息 |
| `unregistered` | 学生表中存在但尚未在班级管理登记 |

学生导入时若遇到未登记的班级，系统会**自动建档**并标记「待补信息」，
不阻断导入流程 —— 这样避免了「必须先建班才能导学生」导致的循环依赖。

### 7. 顺带修复

- **菜单顺序 bug**：「管理」分组下曾因 `menu.filter` 保留了 `MENU` 原序，
  导致实际显示顺序（账号管理 → 数据管理 → 班级名单）与分组定义顺序不符。
  改为按分组 `keys` 顺序取项后修复。

### 新增接口清单

```
GET    /api/classes              班级列表（年级/状态/关键字筛选 + 分页）
GET    /api/classes/:name        单班详情
POST   /api/classes              新增班级
PUT    /api/classes/:name        编辑班级（改班名时联动三处引用）
DELETE /api/classes/:name        删除班级（带引用守卫）
POST   /api/classes/import       批量导入（按班级名匹配，留空=不改动原值）

POST   /api/classes/:name/sync-account   显式联动账号（双写 users.classes + staffs.classes）
```

## 三、部署说明

### 环境要求

- Node.js >= 16
- **零第三方依赖**，无需 `npm install`

### 启动

```bash
node server/index.js          # 默认端口 3000
PORT=8080 node server/index.js   # 指定端口
./start.sh                    # 或用启动脚本
```

访问 `http://localhost:3000`。

**首次启动**会自动创建默认管理员账号 `admin / admin123`，
登录后请立即在「账号管理」中修改密码。

> 本包**不含业务数据**（`data` 目录已排除），首次启动为干净空库。

### 推荐导入顺序

依赖链：**班级管理 → 班级名单 → 教职工名单 → 账号管理**

**第 1 步：班级管理**（最容易踩坑，务必先做）
下载模板，填写：`班级 / 年级 / 专业 / 班主任 / 辅导员 / 纪律委员`
`工号` / `学号` 两列**可先留空**（此时还没导教职工和学生，填不了）→ 导入

**第 2 步：班级名单**
模板 4 列：`年级 / 班级 / 姓名 / 学号` → 导入
三岗位自动从第 1 步的班级管理数据带出，无需再填

**第 3 步：教职工名单**
填写工号 / 姓名 / 班级 / 角色，用于补全第 1 步留空的工号

**第 4 步：账号管理**
批量同步班级岗位到账号

### 三个已知坑

1. **先导入学生会返工**：学生导入时若班级未登记，系统会自动建档并标记
   「待补信息」，之后还得回班级管理补岗位信息
2. **工号学号首次填不了**：依赖关系决定了首次导入时无法填写，属正常，第 3 步补
3. **纪律委员默认无账号**：因其身份是学生，账号联动会显示「未建账号」
