### 账号与权限
- **五类角色**：管理员、权益部、纪律委员、班主任、辅导员（新增后两类只读角色，数据范围限定其所带班级）

## 2.1 增补更新（2026-09-28）⑤：登录态无状态化（修复"2 分钟后被踢"）

- **现象**：用户反馈登录后约 2 分钟无操作即被自动踢回登录页
- **根因 ①（底层 bug，自项目创建起即存在）**：`store.load()` 对所有集合强制"非数组 → 置空"，而登录态 tokens 表是**对象映射**——每次进程重启 tokens 表都被加载成空，所有已登录用户随之失效。部署平台沙箱在空闲约 2 分钟后会回收/调度进程实例，恰好触发该 bug
- **根因 ②（结构性）**：登录态依赖服务端内存态 tokens 表，无法抵御进程回收 / 多实例调度
- **修复**：登录态改为**无状态签名 token（HMAC-SHA256，v2 格式）**——`v2.<userId>.<过期时间>.<签名>`，服务端验签即可鉴权，不依赖任何内存/磁盘表；签名密钥持久化于 `data/secret.key`，进程重启 / 多实例下登录态均有效；有效期 30 天
- **安全边界**：签名采用 timingSafeEqual 防时序攻击；篡改签名 / 篡改 userId / 过期 token 均 401；管理员重置密码后该账号重置前签发的登录态一并失效（`pwdChangedAt`）；账号停用立即失效
- **兼容**：存量旧格式随机 token 仍走 tokens 表鉴权（load bug 修复后可正常加载），已登录用户不受影响；`tokens.json` 不再新增写入
- 验证：/tmp/kqtest7 跨**真实进程重启**（3 次重启 + 删除 tokens 表）登录态全部存活；篡改 / 过期 / 重置密码失效 / 旧 token 兼容共 13 项断言全过

## 2.1 增补更新（2026-09-28）⑥：假单生效状态展示优化

- **背景**：用户反馈"假单明明在请假期间却显示未生效"。排查结论为设计语义而非 bug——系统"生效"指假单实际套用到考勤记录（把点名中的缺勤改判为请假）；请假日期内对应节次尚未有点名记录（或该生未被记缺勤）时，无可改判项，持久状态停留"待生效"，点名提交后会自动对账生效
- **三态展示**：假单列表状态列按当前日期区分展示——「已生效」（绿色，已有考勤被改判）、「待生效」（橙色，请假尚未开始）、「生效中」（蓝色，请假期间内，悬停提示"点名提交后缺勤将自动改判"）、「未生效」（灰色，请假已结束且无可套用缺勤，悬停提示原因）
- **兼容性**：持久状态仍为"已生效/待生效"二值，状态筛选下拉不受影响；仅展示层变化，不改数据与对账逻辑
- 涉及文件：`public/js/pages/leaves.js`（新增 `statusTagOf()` 三态展示函数，状态列渲染改用该函数）
