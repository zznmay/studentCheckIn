# 修改82 · 批量导入点名记录（线下纸质点名表数字化）

> 适用版本：4.6 持续迭代线（修改82，2026-10-11）
> 场景：其他班级使用线下纸质点名表，需将历史点名数据批量录入系统，保证数据完整性。

## 一、功能概述

在「考勤点名」列表页新增**批量导入点名记录**（管理员 / 权益部 / 学院考勤负责老师可见）：

- **长表模型**：一行 = 一名学生一次状态；同一（班级 + 日期 + 节次）的多行自动归并为**一场**点名记录，与线上点名的 `attendance` 结构完全同构。
- **名单驱动**：每场 items 恒等于全量班级名单，表中未出现的学生按「出勤」计入（应到人次不缩水），并在结果中提示人工复核——与线上点名 `POST /api/attendance` 语义一致。
- **来源标记**：`session.source = 'import'`，列表「发起人」旁显示「导入」小标签，支持按来源筛选；**到课率 / 缺勤节数 / 处分重算等全部统计与线上点名完全等权，零区分**。
- **全链路副作用照抄线上**：考勤修改日志（create/update，via=批量导入/批量导入覆盖）→ 假单双向对账（缺勤↔请假自动改判，落 system 日志）→ 处分重算（按学生去重后一次调用）。

## 二、模板与字段映射

「下载导入模板」生成 `点名记录导入模板.xlsx`（服务端实时生成，零静态文件）。

表头：`日期 | 节次 | 班级 | 课程 | 教师 | 学号 | 姓名 | 状态 | 备注`（教师 / 备注可省略整列）。

| 列 | 必填 | 归一化规则 |
|---|---|---|
| 日期 | 是 | 2026-9-23 / 2026/9/23 / 2026年9月23日 / Excel 日期单元格均可 |
| 节次 | 是 | 1-2节/3-4节、1-2、9-10、全天；**空值报错**（不沿用假单"空=全天"语义，防漏填误建全天 7 场） |
| 班级 | 是 | 必须已在「班级管理」登记（修改73 准入口径），空格/全角差异自动校正 |
| 课程 | 是 | 原样入库 |
| 教师 | 否 | 原样入库 |
| 学号 | 是 | 去空白+全角转半角后匹配名单（学号更正场景见下） |
| 姓名 | 是 | 与名单核对，不符报错 |
| 状态 | 是 | 别名归一（下表） |
| 备注 | 否 | 截断 100 字 |

**状态别名归一**（`normAttendanceStatus`）：

- 出勤 ← 出勤 / 正常 / 到 / 到课 / 出席 / √ / ✓
- 迟到 ← 迟到 / 迟 / 晚到
- 缺勤 ← 缺勤 / 旷课 / 旷 / 缺席 / 未到 / 未出勤 / × / ✗
- 请假 ← 请假 / 病假 / 事假 / 公假 / 假（病假 / 事假 / 公假原词会先写入备注前缀；**注意：保存后假单对账可能改写备注**，见第四节）

## 三、校验逻辑与错误处理

逐行校验、逐行报错（**部分成功**：合法行照常导入，非法行跳过）：

| 层级 | 规则 | 错误文案示例 |
|---|---|---|
| 行级 | 必填缺失 | `班级为必填，该行已跳过` |
| 行级 | 状态非法 | `状态"睡觉"无法识别（可用：出勤、迟到、缺勤、请假），该行已跳过` |
| 行级 | 日期/节次非法 | `日期"2031-05-32"无法识别（示例：2026-9-23 或 2026/9/23），该行已跳过` |
| 行级 | 班级未登记 | `……（表中班级「X」），该行已跳过；请核对班级名称，或先在「班级管理」中登记该班级` |
| 行级 | 学号+姓名均不在名单 | `学号"X"未在班级"Y"名单中找到，该行已跳过；……` |
| 行级 | 学号命中但姓名不符 | `学号"X"与姓名"Y"不匹配（名单中该学号为"Z"），该行已跳过` |
| 行级 | 同班同名多条 | `班级"Y"下存在 N 条同名记录……无法判定……，该行已跳过` |
| 行级 | 同场次同学号多行 | `该学生在本场次（日期 节次）出现多行，仅保留第一行，请人工核对` |
| 场次级 | 已存在相同时段 | `班级"X"在 日期 已存在相同时段（节次）的点名记录，该场 N 行已跳过；如需覆盖请勾选「覆盖已有记录」重新导入` |
| 场次级 | 已签字确认 | `……已由任课老师"Z"签字确认，不允许覆盖，该场 N 行已跳过` |

**学号匹配三级策略**（限本班）：
1. 学号精确 / 规范化（去空白、全角转半角）命中 → 采用；
2. 未命中且同班同名**唯一** → 视为学号更正，采用名单学号并 notice；
3. 同班同名多条或均未命中 → 报错跳过。

结果面板：行级统计（导入 N 行 / 跳过 N 行）+ 场次汇总（新建 X 场 / 覆盖更新 Y 场 / 跳过 Z 场）；错误与提示各显示前 20 条，超过时提供**「下载完整明细」**（CSV，含 BOM，Excel 直接打开）。

## 四、重复记录处理（覆盖模式）

- **默认**：命中同（班级+日期+节次）的已有记录 → 该场整体跳过并报错。
- **勾选「覆盖已有记录」**：仅覆盖表中出现的学生的状态与备注（对齐 PUT 语义，名单其余学生保持原值）；状态无变化的行计入「无变化」。
- **硬拒绝**：`confirmStatus='confirmed'`（任课老师已签字）的记录无论是否勾选覆盖一律跳过，防止覆盖已确认数据。
- 服务端**幂等**：网络重试重发已导入的行只会命中「已存在相同时段」跳过语义，不会重复建档。

## 五、假单对账联动（重要口径说明）

导入的每场点名都会触发与线上点名相同的**假单双向对账**（`reconcileLeavesForSession`）：

- 已有假单覆盖该日期节次 → 缺勤改为请假，备注改写为 `假单·病假：事由`；
- 标了「请假/病假/事假」但**当天无假单** → 被自动改判**缺勤**（备注注明原因），并落「假单自动校正」system 日志。

因此：线下纸质表标了"病假"但系统无对应假单时，导入结果为**缺勤**——这是有意设计，与线上点名保存后的行为完全一致（防止绕过假单管理随意记假）。

## 六、前端分批上传设计（部署平台适配）

部署平台网关对「单连接累计上行」有限制（修改79 实测），导入采用三段式：

1. `POST /api/attendance/import/parse`：上传 xlsx 原文件（压缩后体积小）→ 服务端解析归一化（定位表头、支持前导说明行、学号姓名均空的说明行静默跳过）→ 归一化行**下行**返回（下行不受网关限制）；
2. 前端按场次分组、贪心分批（每批 JSON ≤192KB，同场次行不拆批）；
3. 逐批 `POST /api/attendance/import` + `withRetry` 自动重试（6 次、指数退避；网络层失败自动换新连接）；某批重试耗尽即记录并继续后续批，全部完成后提示可重新上传（幂等，已导入数据不受影响）。

`withRetry` 已自 `dataManage.js` 公共化至 `public/js/api.js`（行为不变，数据管理分片上传回归通过）。

## 七、接口清单

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/templates/attendance` | 登录 | 下载导入模板 |
| `POST /api/attendance/import/parse` | admin / rights / collegeOfficer | xlsx → 归一化行 `{rows:[{_row,date,periods,className,courseName,teacher,sid,name,status,note}], total}` |
| `POST /api/attendance/import` | 同上 | 单批导入 `{rows, overwrite}` → `{total, createdSessions, updatedSessions, unchangedSessions, skippedSessions, importedRows, unchangedRows, skippedRows, failed, errors, errorsCount, notices, noticesCount, sessions[]}` |
| `GET /api/attendance?source=import\|online` | 原有 | 来源筛选（不影响统计） |

单批接口限流 60 次/分钟、parse 30 次/分钟。核心导入逻辑在 `importAttendanceRows()`（server/api.js），路由只做壳。
